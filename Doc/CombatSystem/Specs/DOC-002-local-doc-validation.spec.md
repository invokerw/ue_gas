## 1. 目标与范围

将目录迁移后的检查固化为无第三方 Python 依赖的本地命令和正反例测试。命令失败时给出文件、错误类型和位置，可在临时目录运行测试，不能修改被检查的文档。

范围：`Tools/validate_docs.py`、对应测试、使用说明和项目入口。Non-Goals：远端 CI、UE 运行时、用户验收决定、代码关系索引、模型评估、自动提交和推送。

## 2. 当前事实与依据

- [DOC-001](DOC-001-document-system-migration.spec.md) 已完成文档迁移，检查命令仍需成为可复用工具。
- 本轮初版脚本已能发现断链，但会误读代码示例中的链接；用“SAM/待验收”关键字校验台账会阻碍合法状态变化。
- 当前没有远端 CI；本地命令是单人协作的唯一文档 Gate。

## 3. 行为与契约

- 从脚本位置定位仓库，支持 `--root` 指定测试仓库和 `--report` 保存 JSON。
- 检查根 README、Agent 入口和 `Doc/**/*.md`；忽略生成目录。
- 检查必需文件/目录、残留平铺文件、实际链接指向的旧路径、尾随空格及 Spec 必需字段/章节。
- 支持内联、图片和引用式 Markdown 链接、带括号的路径、角括号或 URL 编码的空格路径；代码块和行内代码不当成链接。
- 仅验证本地目标路径。外部 URL 可达性、页内锚点、原始 HTML 和文档语义需单独审查。
- 台账状态可以合法变化；不得通过固定测试数量、SAM 状态或版本字符串判断项目完成度。
- 成功退出 0，校验失败退出 1；参数/报告写入错误退出 2。缺文件和编码错误给出诊断，不输出 Python traceback。

## 4. 验收标准（AC）

- [x] AC-01：真实仓库通过；删除必需入口或制造断链时失败。
- [x] AC-02：代码示例不误报；括号/空格路径、图片和引用式链接正确处理。
- [x] AC-03：合法台账状态变化通过；缺失 Spec 元数据或验收章节失败。
- [x] AC-04：校验只读；错误退出码及 JSON 报告可供本地工具消费。
- [x] AC-05：提交本地通过的正反例测试，并明确不依赖远端 CI 或 PR 流程。

## 5. 测试矩阵与命令

| 场景 | 命令 | 预期 |
| --- | --- | --- |
| 临时仓库正反例 | `python3 -B -m unittest discover -s Tools/Tests -p 'test_validate_docs.py' -v` | 全部通过，临时内容自动清理 |
| 当前文档 | `python3 -B Tools/validate_docs.py --report Saved/DocValidation/report.json` | 退出 0，报告无错误 |
| 差异 | `git diff --check` | 无空白错误；另检查未跟踪新文件 |

已有初版实现先于本 Spec；以下测试用于修正初版的已知缺陷，不补写“先有完整 Red”的历史。
